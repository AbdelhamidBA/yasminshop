# Phase 5: Dashboard, Notifications, Sub-Admins & Mass Discount

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Implemented codebase idioms are authoritative.

**Goal:** Admin dashboard with welcoming hero + statistics + charts (clients, orders per day/week/month/year, finances, orders-by-status); a notification system with an admin bell + web push on new orders; sub-admins management (admin-only); and a global mass-discount control that applies/removes a single discount across all products with cart-display awareness.

## Global Constraints

- Everything from Phases 1–4 binds (millimes, catalogs parity + real Arabic, logical utilities, archivedAt, scalar guards, server-authz per page/action/route, Base UI `render=`/`items`/`onClick`, conventional commits + Claude trailer, version-drift). The user's pm2 dev server on port 3000 is REUSED, never killed; `touch next.config.ts` after catalog/schema edits; manual order #1 + seeds never mutated by tests.
- **Spec §6e Phase-5 bindings implemented here:** (1) when the mass-discount toggle is on, the storefront cart display re-prices or shows a notice — since cart lines store add-time effective prices, add a cart-page server-passed `massDiscountPct` and a one-line "prices updated at checkout" notice when it differs from a line's implied discount; simplest correct choice: recompute the cart totals panel with current effective prices server-side is impossible (cart is client) — so show the notice unconditionally when massDiscountPct is active (documented). (2) `getMassDiscountPct` integer-0–100 contract preserved. (3) reset-token invalidation + SMTP note deferred to Phase 6 unless trivial (do NOT expand scope).
- **Charts:** use a dependency-free inline-SVG chart approach OR add `recharts` (the spec named Recharts) — DECISION: add `recharts` (self-contained, themeable) as a dependency; wrap each chart in a small client component fed server-computed data (never raw DB rows to the client). Charts must be theme-aware (read CSS variables or accept color props) and RTL-tolerant.
- **Stats are money-safe:** all revenue/finance figures are integer millimes summed in SQL/Prisma aggregates, formatted with `formatMillimes` + currency at render. Finances count CONFIRMED + DELIVERED orders as revenue (PENDING = pipeline, CANCELED = excluded) — matching the spec's finance intent; state this in code.
- **Roles:** dashboard + notifications = `requirePageStaff` (both admin + sub-admin see the dashboard). Sub-Admins management = ADMIN only (page + all actions; sub-admin gets 404/redirect). Mass discount control = ADMIN only. Push subscription endpoints = `requireStaff` (any staff device can receive order alerts).
- Web push uses the `web-push` library with VAPID keys from env (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`); `.env.example` documents them; a dev fallback generates+logs keys if absent (documented; never commit real keys). The service worker lives at `public/sw.js`. Push is best-effort: failures (410 Gone) prune the subscription; the in-app Notification bell is the reliable channel and works without push.
- Per task: tsc + npm test green before commit; UI tasks HTTP-verified with role jars; e2e suites stay green (run in Task 9).
